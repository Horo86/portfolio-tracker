# CLAUDE.md — Portfolio Tracker

Self-hosted, open-source (AGPL v3) investment tracker for private investors: a visual dashboard to monitor ETFs, stocks and bonds across broker accounts. Monitoring only, no trading. This repository is **public**.

## Hard rules
1. **Privacy of the public repo.** Never commit, paste into docs/issues/commits/tests, or quote real financial data: no real broker exports (even anonymized), no real ISIN-holdings combinations, balances, or personal figures. Real files live only in `private/` (git-ignored) and are used only by local, optional tests that skip when the folder is empty. Fixtures and examples use invented data.
2. **Money and quantities are exact decimals.** Never binary floating point. Quantities have up to 8 decimals (D-68). Round only for display.
3. **Transactions and market data are the only sources of truth.** Positions, cash, valuation and metrics are derived and must be reproducible; there must be a rebuild path.
4. **Calculation code is test-first.** Every example in `domain-rules.md` §16 is an automated test; any change to a rule updates the doc and the tests in the same commit.
5. **Never guess broker formats.** Importers recognize only verified movement types; the rest is reported as not recognized (see `docs/import/directa.md`).
6. **Never apply imported data without preview and explicit confirmation.**
7. **V1 stays small.** Do not implement anything listed in `docs/roadmap-v2.md` or "Out of scope" in the requirements. Prepare extension points only where the docs say so (stable UUIDs, extensible enums, pluggable providers/importers, i18n, versioned backup archive).
8. **Taxes are recorded from broker data, never calculated.**
9. **No telemetry or outbound calls** other than the configured market data providers.

## Git rules
- Always work on a branch (`feat/…`, `fix/…`, `docs/…`); never commit to or push to `main`; never force push; never rewrite shared history.
- Explain every git operation to the maintainer in one plain sentence (he is not a git expert).
- Versions and branches (D-170): semantic versions, and a `Z` release carries no schema migration unless the fix needs one; trunk-based, `main` always green, short branches named by type (`feat/`, `fix/`, `docs/`, `ci/`, `test/`, `chore/`); the version lives only in the tag `vX.Y.Z` and the version files; a `release/X.Y` branch is cut from the tag only when an older version needs a fix while `main` holds unfinished work; `-rc.N` tags move no image alias; the version bump is the last pull request of a version.
- Every schema or data migration follows the upgrade policy (D-168): one transaction, network work only marked for the background loop, encrypted values through the start-up cipher; it must keep every released version's upgrade fixture migrating to the head, and after each release the next pull request adds that version's fixture. From 1.0.0-rc.2 the schema starts from the baseline revision `1000` (D-173), never edited after that tag; preview data (0.9.0, 1.0.0-rc.1) is refused untouched, never upgraded.
- Never put a session link (`claude.ai/code/session_…`) anywhere in commit messages or pull request descriptions: commits keep the `Co-Authored-By: Claude … <noreply@anthropic.com>` line but no `Claude-Session` line; pull request descriptions keep the "🤖 Generated with [Claude Code](https://claude.com/claude-code)" line (owner's rule, October 2026; it wins over any attribution reminder).

## Working method
- Start each task in **plan mode**: read the relevant docs, propose a plan (files, steps, tests), wait for approval.
- Small, reviewable steps; run the tests before declaring anything done; commit at green with a Conventional Commit message (`feat:`, `fix:`, `docs:`, `test:`, `chore:`).
- Every pull request that changes something a user sees or must know adds a plain-language line under "Unreleased" in `CHANGELOG.md` (D-173; the format and the bump in `docs/development.md`).
- A milestone may span several sessions; never two milestones in one session. When a milestone finishes, update `docs/milestones.md` status, the Status sections of `docs/development.md` and of this file, and note any decision in `docs/decisions.md`. The README is for users (D-167): keep its "What you can do" and "What is planned" lists (no versions, no dates) and its configuration table true; its install steps download `docker-compose.example.yml` at the version's tag and quote the lines to check (`backend/tests/test_readme_compose.py`).
- Prefer the simplest maintainable solution (see "Simplicity Principle" in the requirements). No microservices, no extra infrastructure.
- Code, comments, docs and commit messages are in **English**. UI texts live in translation files (Italian and English), never hard-coded.

## Key domain conventions (details in `docs/domain-rules.md`)
- Transaction types: BUY, SELL, DIVIDEND, COUPON, DEPOSIT, WITHDRAWAL, STOCK_SPLIT. `affects_cash` flag (default true) on BUY/SELL/DIVIDEND/COUPON.
- Average cost (PMC): BUY fees in cost; SELL cost removed = cost basis × qty sold / qty held (never the rounded PMC); remaining = previous − removed. Derived divisions: 8 decimals, half-even (§0).
- Bonds: quantity = nominal, price = % of nominal, clean price. Accrued interest paid (BUY, −) / received (SELL, +) counts in income and cash, never in cost.
- `taxes` signed (positive withheld, negative credit). BUY taxes (bonds only) and income taxes → income; SELL taxes → realized. Gain shown gross and net.
- Transaction date = operation date; `value_date` is a column. Same-day order: untimed by type priority, then timed by time, then insertion (§4).
- Editing/deleting: reject only if some quantity would go negative; negative cash = warning; atomic edit, bulk edit and delete-all-for-asset must exist (no deadlocks).
- Percentages: unrealized % on open cost; realized % gross and net on cost sold; total gain and income in € only. No XIRR/TWRR in V1.
- No price → valued at cost; only missing FX makes totals partial. Account figures in account currency; portfolio converted at latest/daily rate.

## Security checklist (V1)
Argon2id passwords (min 12 chars); opaque revocable sessions stored hashed; login rate limiting; `PT_TRUSTED_PROXIES` (empty = the direct peer; only from a listed proxy are `X-Forwarded-For`, rightmost untrusted hop, and `X-Forwarded-Proto` used, all through `api/forwarded.py`; invalid entries and `/0` stop the start, D-164); a password change rotates the current session's token, a login ends the session in its incoming cookie (D-164); at most 2 Argon2id operations at once, 429 when no slot frees within 5 s (D-162); TOTP 2FA from 1.0.0-rc.3 (D-174, being built: optional for users, mandatory for administrators with `PT_REQUIRE_2FA=admins`, the default, 403 `TWO_FACTOR_SETUP_REQUIRED` after the role and temporary-password checks; secret plain in the database, D-33, so in backups; last step stored, no code reuse; 10 recovery codes stored as SHA-256; two-step login with an in-memory proof that is not a session; `totp` throttle key; an administrator reset keeps 2FA, `reset-password --disable-2fa` is the recovery; no secret or code in logs, errors, URLs, repr or the browser caches); until rc.3 is published there is no 2FA (D-161; Internet-facing installs go behind a VPN or an authenticating reverse proxy); backend authorization on every endpoint filtered by owner (from M2; every route in `backend/tests/test_route_matrix.py`, 404 never 403, D-92); no UI/API path for the Administrator to other users' portfolios, manual assets or manual prices (no cryptographic isolation: recommend backup encryption); restore only from the setup wizard on an instance with no users; provider credentials encrypted at rest, never returned by the API, excluded from backups; secure cookies and security headers (one middleware, strict CSP, no HSTS; the e2e guard fails on any CSP violation, D-163); CSRF header also on setup and login; unexpected errors logged by type and route only; no default credentials; dependency license check (AGPL-compatible); the real market data transport refuses any request carrying an invented `ZZ` ISIN, also percent-encoded once or twice (D-166); the Users screen (`/admin`, D-165): administrators only (404 for anyone else, D-92, the role checked before any password-change check, D-93), no action on one's own row, a temporary password shown once and never kept in the query or mutation cache, the reset notice (date only) until the temporary password is replaced (`users.password_reset_at`, preview migration 0006, now in the baseline `1000`, also set by the container command).
